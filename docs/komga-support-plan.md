# KavaReader Komga 지원 계획

2026-10-06 현재 작업 디렉터리의 구현과 Komga 공식 문서를 기준으로 작성했다. 모든 구현 항목은 아직 미완료다. 아래 타입과 파일 이름은 제안이며 구현 단계에서 기존 구조에 맞춰 확정한다.

## 목표와 첫 출시 범위

기존 Kavita 연결, 독서 기록, 로컬 파일 기능을 유지하면서 Komga 서버에서도 탐색 → 만화 읽기 → 진행률 저장 → 이어 읽기를 제공한다.

- 서버 URL + API 키 연결을 먼저 구현한다. 계정 로그인은 후속 확장으로 둔다.
- 현재처럼 활성 서버 연결은 하나만 사용하고 Kavita와 Komga의 설정 프로필은 따로 보관한다. 여러 서버의 서재를 동시에 합치는 기능은 후속 확장으로 둔다.
- 첫 출시는 이미지 기반 만화 읽기를 중심으로 한다. PDF는 Komga의 페이지 이미지 API로 읽을 수 있는 것을 실제 확인한 뒤 포함한다. 텍스트 EPUB은 별도의 독서 위치 모델과 리더 연동 단계로 둔다.
- 목록, 검색, 작품 상세, 표지, 페이지 보기, 미리보기, 다음 권 이동, 읽는 중, 이어 읽기, 읽음/안 읽음 표시를 지원한다.
- Komga 즐겨찾기는 우선 앱 내부에서 서버·계정별로 저장한다. Kavita의 Favourite/Want to Read 연동은 유지한다. Komga의 컬렉션/읽기 목록을 Kavita의 Want to Read와 동일한 기능으로 취급하지 않는다.
- 메타데이터와 추천의 현재 흐름을 공통화해 Komga에서도 지원 가능한 기능을 제공한다. 서버의 장르·태그·줄거리와 사용자의 수동 AniList 연결을 먼저 존중한다.
- 신규 오프라인 다운로드, 범용 OPDS 리더, Komga 컬렉션/읽기 목록 편집은 후속 확장으로 둔다. 목록·표지 캐시 지원과 완전한 오프라인 독서는 별개다.

## 현재 코드에서 확인한 작업 지점

| 지점 | 현재 상태 | 필요한 변경 |
| --- | --- | --- |
| `LibraryService.swift` | 프로토콜이 있지만 상세 조회 인자가 `kavitaSeriesId: Int`이고 진행률 저장 계약이 없음 | 서버 공통 ID와 이미지·진행률·이어 읽기 계약 |
| `LibraryServiceFactory.swift` | 항상 `KavitaLibraryService` 생성 | 서버 종류와 검증된 연결 프로필로 생성 |
| `LibraryModels.swift` | 서버 ID가 Kavita 정수 ID이고 권/챕터 필드에 결합됨 | 앱 UUID와 서버 원본 ID 분리, Book 매핑 |
| `ReaderViewModel.swift`, `SeriesDetailView.swift` | 여러 기능에서 `KavitaLibraryService` 직접 캐스팅 | 서비스 인터페이스를 통한 이미지·독서 위치 처리 |
| `KeychainHelper.swift`, 서버 설정 | Kavita 인증, 연결 종류, 세션 범위에 결합 | Komga 독립 프로필과 공통 연결 수명 관리 |
| 목록/챕터/진행률/미리보기 저장소 | Kavita ID·DTO·표지 URL 재구성을 사용 | 스키마 버전과 이전 데이터 이관, 출처별 격리 |
| `CoverImageCache`, `PagePreviewCache`, 추천 미리보기 | URL 기반 이미지 흐름이 있음 | 헤더 인증을 전달하는 요청과 계정별 캐시 키 |
| `ContentView`, `LibraryViewModel`, `LibraryPlusViewModel` | Kavita 표시명, 출처 종류와 서비스 타입 참조 | 활성 공급자 표시, 공통 메타데이터·미리보기 흐름 |

기존 `plan.md`는 작성 시점이 오래되어 현재 코드와 다른 항목이 있다. 이 계획은 현재 코드에서 확인한 상태를 기준으로 한다.

## 1단계 — API 계약과 지원 범위 확정

- [ ] 공식 OpenAPI와 대상 서버의 `/swagger-ui.html`로 인증, ID 타입, 페이지 번호, 진행률, 정렬, 권한, 페이지네이션을 확인한다.
- [ ] 지원할 최소 Komga 버전과 첫 출시 형식을 명시한다. 공개 문서는 확인 시점에 1.28.1을 표시하지만 이것을 곧바로 최소 지원 버전으로 간주하지 않는다.
- [ ] 정상/빈 목록, 여러 페이지 목록, 문자열 ID, 미분석 책, 접근 제한 책, 진행 중/완독 책의 비밀정보 없는 fixtures를 마련한다.
- [ ] Komga Library → 서버 라이브러리, Series → 앱 작품, Book → 앱 읽기 단위로 매핑한다. Kavita의 Volume은 Kavita 어댑터 내부 정보로 둔다.
- [ ] 권 순서, 단권, Specials 처리 기준을 정한다. 책 제목이나 파일명만으로 Specials를 추측하지 않는다.
- [ ] API가 제공하는 기능과 앱 내부 기능을 구분한 기능표를 작성한다.

참조할 API 계약:

| 용도 | 확인된 경로/방향 |
| --- | --- |
| 인증 | `X-API-Key` 헤더; 후속 계정 로그인은 Basic 인증 |
| 작품 목록 | `POST /api/v1/series/list` |
| 책 목록 | `POST /api/v1/books/list`를 사용하고 시리즈 조건으로 범위를 제한 |
| 페이지 이미지 | `GET /api/v1/books/{bookId}/pages/{pageNumber}` |
| 진행률 변경 | `PATCH /api/v1/books/{bookId}/read-progress` |
| 다음에 읽을 책 | `GET /api/v1/books/ondeck` |

위 목록 외에 라이브러리, 사용자, 상세, 표지, 진행 중 책 필터, 읽음/안 읽음 요청의 정확한 계약을 구현 전 확인한다. Deprecated 목록 API는 새 구현의 기본 경로로 사용하지 않는다.

완료 기준: 화면별 데이터 매핑, 최소 버전, 요청/응답 fixtures, 기능별 지원 여부가 확정된다.

## 2단계 — 서버 공통 모델과 저장 데이터 이관

- [ ] `ServerKind`와 `ServerConnection`을 도입한다. 서버 종류, 정규화 URL, 확인된 계정 식별자, 인증 방식과 인증 갱신 상태를 구분한다.
- [ ] 원본 서버 ID를 문자열로 보존하는 공통 참조 타입을 만든다. Komga ID를 정수로 변환하거나 앱 UUID로 원본 ID를 대체하지 않는다.
- [ ] 화면의 `Identifiable` UUID는 유지한다. 서버 종류·연결·엔티티 종류·원본 ID로 안정적인 식별 관계를 만든다.
- [ ] `LibraryServicing`에 상세 조회, 인증된 이미지 요청/조회, 진행률 조회/저장, 이어 읽기, 읽음 상태 변경을 추가한다. 공급자별 선택 기능은 capability로 표현한다.
- [ ] `ProgressDto`/`ContinuePointDto`는 Kavita 응답 변환에 사용하고 공통 화면에는 공급자 독립적인 독서 위치 모델을 전달한다.
- [ ] 리더, 상세, 읽기 저장 큐, 읽기 상태, 독서 설정, 분류, 수동 메타데이터 연결, 추천 미리보기의 정수 ID 의존성을 함께 정리한다.
- [ ] 이전 Kavita 연결에는 서버 종류를 Kavita로 적용한다. 기존 Keychain 키와 기존 UUID·계정 범위를 연결하는 호환 경로를 마련한다.
- [ ] 독서 기록, 즐겨찾기, 수동 AniList 연결, 사용자 설정 등 사용자 데이터를 보존한다. 새 저장 형식으로 이관이 완료되기 전에 원본을 제거하지 않는다.
- [ ] 목록/이미지처럼 다시 받을 수 있는 캐시는 필요 시 재생성한다. 캐시 재생성과 독서 기록 초기화를 구분한다.
- [ ] 먼저 Kavita 어댑터만으로 공통 구조를 연결해 기존 동작을 확인한다.

완료 기준: 화면과 공통 저장소가 Kavita 서비스를 직접 캐스팅하지 않아도 기존 Kavita 기능이 작동하고, 이전 저장값으로 시작해도 독서 상태와 설정이 복원된다.

## 3단계 — Komga 연결과 인증된 이미지 요청

- [ ] 서버 설정에 Kavita / Komga 선택을 추가하고 활성 연결을 표시한다.
- [ ] `KomgaServerSettingsView`, 연결 검증기, Keychain 프로필을 추가한다. URL 정규화와 프록시 하위 경로를 보존한다.
- [ ] API 키로 사용자 및 라이브러리 접근을 검증한 뒤에만 활성 연결을 변경한다. 실패·취소·Keychain 저장 실패 시 이전 연결을 유지한다.
- [ ] 요청 생성 계층에서 JSON·표지·본문 이미지·미리보기에 같은 인증과 세션 규칙을 적용한다. API 키를 이미지 URL에 붙이지 않는다.
- [ ] 이미지 캐시 키를 URL만으로 만들지 않고 서버 종류·계정·원본 엔티티 ID·이미지 종류·페이지로 구분한다. 비밀정보를 로그와 파일명에 남기지 않는다.
- [ ] 기존 서버 범위 리다이렉트 제한을 공통 연결에도 적용한다.
- [ ] 서버 전환 시 기존 비동기 요청과 화면 갱신을 무효화한다. 진행률 요청은 시작 시점의 연결을 캡처해 새 서버로 전송되지 않게 한다.
- [ ] `LibraryServiceFactory`가 연결 종류에 따라 Kavita 또는 Komga 서비스를 생성하게 한다.

완료 기준: Komga 연결/실패/재연결/앱 재시작이 동작하고, 같은 URL의 계정 전환과 프록시 하위 경로에서도 인증과 이미지 캐시가 섞이지 않는다.

## 4단계 — 서재·검색·작품 상세

- [ ] `KomgaLibraryService`와 Komga DTO를 구현하고 공통 모델로 변환한다.
- [ ] 라이브러리와 작품 목록을 페이지별로 가져온다. 요청 취소, 중복 제거, 정렬 안정성, 빈 목록을 처리한다.
- [ ] 현재 앱의 로컬 검색이 전체 작품을 찾을 수 있도록 작품 카탈로그의 모든 페이지를 수집한다. 페이지마다 목록을 갱신하되 첫 페이지를 전체 결과로 저장하지 않는다.
- [ ] 모든 작품의 책 상세를 한 번에 가져오지 않는다. 작품별 책은 상세 진입과 필요한 이어 읽기 조회에서 가져온다.
- [ ] 최근 추가, 전체 작품, 읽는 중 섹션을 매핑하고 섹션 종류를 표시 문자열과 분리한다.
- [ ] 작품 상세에 제목·작가·줄거리·권 목록·권 표지를 표시한다. 메타데이터 누락과 읽을 수 없는 책을 처리한다.
- [ ] 앱 내부 Komga 즐겨찾기와 사용자 분류를 서버·계정·작품별로 저장한다.
- [ ] 서재와 챕터 목록 캐시를 공통 모델로 저장하고 표지 요청은 공급자가 재구성한다.
- [ ] 화면의 고정된 Kavita 표시와 출처 값을 활성 공급자에 맞춘다. 새 사용자 문구는 한국어와 영어를 제공한다.

완료 기준: 여러 페이지에 걸친 서재에서도 작품이 누락되지 않고 검색·상세·표지·즐겨찾기가 동작하며, 앱을 다시 열 때 저장된 목록이 복원된다.

## 5단계 — 만화 리더 연결

- [ ] 기존 리더의 한 페이지/두 페이지/세로 스크롤, 읽기 방향, 확대, 사전 로딩을 공통 이미지 요청에 연결한다.
- [ ] 앱의 1부터 시작하는 페이지 번호와 Komga 요청 번호의 관계를 어댑터 안에서 확정한다. Kavita의 `page - 1` 변환을 Komga에 그대로 적용하지 않는다.
- [ ] 본문, 첫 이미지 사전 로딩, 페이지 미리보기, 추천 미리보기 모두 동일한 번호 변환을 사용한다.
- [ ] 책 순서에 맞춰 이전/다음 권 이동과 마지막 권 처리를 연결한다.
- [ ] 페이지 스트리밍 권한 부족, 분석 중/실패, 삭제된 책, 이미지 실패를 구분한다. 미지원 형식은 열기 전에 안내한다.
- [ ] PDF 페이지 이미지 지원과 iOS에서 처리할 이미지 형식/변환 요청을 실제 서버에서 확인한다.

완료 기준: 첫·중간·마지막 페이지가 맞고 기존 리더 조작, 권 이동, 모든 미리보기가 정상이다. 이미지·미리보기 조회만으로 진행률을 저장하지 않는다.

## 6단계 — 진행률 동기화와 이어 읽기

- [ ] Book 진행률을 공통 독서 위치로 변환하고 페이지와 완독 여부를 서버 계약대로 저장한다.
- [ ] 기존 직렬 저장 큐를 문자열 원본 ID와 연결 범위에 맞춘다. 빠른 페이지 이동, 종료, 권 이동에서 오래된 저장이 새 위치를 덮어쓰지 않게 한다.
- [ ] 진행 중인 책과 다음 미독 책을 함께 고려해 이어 읽기 목록을 만든다. `ondeck`만으로 목록을 만들지 않는다.
- [ ] 다른 기기의 위치 변경, 서버에서 안 읽음으로 변경한 상태, 뒤로 이동한 위치도 받아들인다. 단순히 큰 페이지 번호를 우선하지 않는다.
- [ ] 서버 저장 성공 위치와 기기의 미전송 위치를 구분하고 실패 후 재시도 규칙을 유지한다.
- [ ] 상세 읽기 버튼, 홈 이어 읽기, 읽는 중 책갈피, 완독 체크를 같은 상태로 갱신한다.
- [ ] 읽음/안 읽음 표시와 읽는 중에서 제거의 서버 기능/앱 내부 기능을 구분한다. 제거가 서버 독서 기록 삭제로 이어지지 않게 한다.
- [ ] 페이지 수가 바뀌거나 책이 삭제된 경우 복원 위치를 검증한다.

완료 기준: 앱 → Komga 웹 리더 → 앱 사이에서 위치와 완독 상태가 일치한다. 통신 실패·재시작·서버 전환·안 읽음 변경에도 다른 계정 기록과 섞이거나 과거 위치로 덮어쓰지 않는다.

## 7단계 — 메타데이터·추천 통합과 출시 검증

- [ ] Komga의 장르·태그·작가·줄거리를 공통 메타데이터로 전달한다. 수동 AniList 연결 우선과 기존 외부 검색의 정확한 제목 매칭 규칙을 유지한다.
- [ ] `LibraryPlusViewModel`의 Kavita 서비스/정수 ID 의존성을 제거하고 장르 탐색, 홈 추천, 일일 추천 저장본, 추천 미리보기를 연결한다.
- [ ] 지원하지 않는 서버 기능은 capability로 구분해 해당 동작을 숨기거나 대안을 안내한다. 무의미한 오류나 전체 홈 로딩 실패로 이어지지 않게 한다.
- [ ] 인증 헤더, 하위 경로, 문자열 ID, 페이지네이션, 페이지 경계, 진행률 순서, 저장값 이관, 서버/계정 전환에 대한 URLSession 목 기반 테스트를 작성한다.
- [ ] 기존 Kavita 직접 연결/API 키/계정 로그인/OPDS 주소 연결과 로컬 CBZ·ZIP 및 기존 EPUB 읽기의 회귀 확인 항목을 제공한다.
- [ ] 실제 Komga 서버에서 일반 계정, 큰 서재, 루트/하위 경로 배포, 만화/PDF, 네트워크 끊김을 확인한다. 실제 서버 정보는 비밀정보를 제거한 뒤 fixtures에 반영한다.
- [ ] `docs/architecture.md`, API 문서, README, 필요한 설정·지원 안내를 갱신한다.

저장소 운영 규칙에 따라 컴파일·테스트 빌드·앱 실행은 사용자가 수행한다. 에이전트는 필요한 테스트 코드와 수동 확인 절차를 제공하고 실제 실행 결과를 확인한 뒤 검증 상태를 기록한다.

완료 기준: 기존 Kavita와 로컬 파일 기능의 회귀 확인 및 실제 Komga의 탐색·읽기·동기화 확인이 끝나고, 지원 버전·형식·계정 권한·후속 기능이 문서에 명시된다.

## 구현 순서와 출시 경계

1 → 2 → 3 → 4 → 5 → 6 → 7 순서로 진행한다. 2단계에서 기존 Kavita 동작을 확인한 뒤 Komga 요청을 연결한다. 캐시 격리는 첫 이미지 연결 전에, 기록 이관은 공통 ID 전환과 동시에 처리한다.

- 3단계: 내부 연결 확인 가능.
- 5단계: 내부 탐색·읽기 확인 가능. 진행률 연동이 완료되지 않았으므로 정식 Komga 지원으로 배포하지 않는다.
- 7단계: 첫 지원 버전 출시 가능.

첫 출시 이후에는 계정 로그인, Komga 컬렉션/읽기 목록, 텍스트 EPUB과 정확한 독서 위치 동기화, 여러 서버 통합, 오프라인 다운로드를 각각 별도 단계로 확장한다.

## 주요 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 공통 ID 도입으로 기존 기록/수동 연결이 끊김 | 기존 UUID 보존과 버전별 저장값 이관 테스트를 먼저 구현 |
| 이미지 URL이 같아 다른 계정의 캐시를 재사용 | 요청 인증과 별개로 연결/계정 범위가 포함된 캐시 키 사용 |
| `ondeck`에 진행 중 책이 없어 이어 읽기 누락 | 진행 중 책과 다음 미독 책을 따로 조회·병합 |
| Komga 도입 후 메타데이터/추천만 빈 화면 | 탐색/리더 외에 LibraryPlus 경로도 공통 계약으로 전환 |
| 큰 서재에서 작품 누락 또는 요청 폭증 | 작품 페이지네이션 완료 여부 관리, 책 상세 지연 조회, 취소·중복 요청 처리 |
| 구버전 서버의 API 차이 | 최소 지원 버전을 1단계에서 명시하고 확인된 범위만 지원 |
