# 아키텍처 개요

## 현재 시스템

- **KavaReader**: SwiftUI로 만든 iOS 앱. 프로젝트 배포 대상은 iOS 26이며 라이브러리 탐색, 작품 상세, 챕터 선택, 만화 리더, 설정 화면을 제공합니다.
- **Kavita**: Synology NAS에서 운영하는 만화 서버. 앱은 NAS 파일을 직접 읽지 않고 Kavita가 제공하는 HTTP API를 사용합니다.
- **서버 측 구성요소**: 현재 별도 어댑터 서버나 Kava 전용 NAS 서비스는 없습니다.

Paperback과 Kavya는 사용자가 현재 만화를 읽는 방식이자 API 동작을 참고한 출처입니다. KavaReader가 Paperback 익스텐션을 가져오거나 Kavya 코드를 실행하는 구조는 아닙니다. 현재 구현은 Kavita API 클라이언트를 앱 안에 둔 형태입니다.

## 코드 구조와 요청 흐름

1. 설정 화면에서 서버 URL과 API Key를 입력하거나, Kavita 설정의 OPDS 주소 입력란에서 연결합니다. `http(s)://서버[/하위경로]/api/opds/인증키`에서 서버 URL과 키를 추출합니다. OPDS로 입력한 HTTP 주소는 요청 전에 HTTPS로 전환하며, 명시된 HTTP 기본 포트 80은 HTTPS 기본 포트로 전환하고 그 밖의 포트와 역방향 프록시 하위 경로는 유지합니다. `KavitaAPIKeyVerifier`로 후보 주소의 Plugin 인증과 Bearer 토큰을 사용한 Library API 접근(JSON 배열 응답)을 모두 확인한 뒤에만 API Key를 Keychain에 저장하고 활성 서버 주소를 바꿉니다. 하위 카탈로그 URL도 지원하며 주소 오류·HTTPS 실패·인증 실패·취소·Keychain 저장 실패 시 기존 활성 서버와 인증 정보를 유지합니다. HTTPS 실패 시 HTTP 재시도나 인증서 검증 우회는 하지 않으며, 기존 서버 범위 리다이렉트 제한을 적용합니다. OPDS 입력은 화면 상태로만 유지하고 성공 후에만 비웁니다. 직접 입력 연결의 HTTP/HTTPS 선택은 기존대로 유지합니다. 실제 목록·리더 통신은 기존 Kavita API를 사용하며 OPDS 피드를 읽는 별도 공급자는 추가하지 않습니다.
2. `LibraryServiceFactory`가 URL을 확인하고 `KavitaLibraryService`를 만듭니다. `LibraryServicing` 인터페이스가 있어 서비스 교체 지점은 있지만, 서버 구현은 Kavita 전용이며, 로컬 CBZ·ZIP은 `LocalComicStore`를 통해 별도로 읽습니다.
3. 라이브러리 화면은 `POST /api/Series/recently-added-v2`, `POST /api/Series/all-v2`, `POST /api/want-to-read/v2`에 빈 JSON 객체 `{}`를 보내 전체 페이지의 목록을 가져옵니다. Want to Read의 작품은 **Favourite** 카테고리에 표시하고, 목록이 비어 있어도 카테고리는 유지합니다. 전체 작품 중 `pagesRead > 0`이고 아직 전체 페이지를 다 읽지 않은 작품은 **읽는 중** 카테고리에도 표시합니다. 홈은 각 카테고리의 일부만 표시하고, 카테고리 제목이나 더 보기 화면을 누르면 저장된 해당 카테고리의 전체 목록을 사용합니다.
   검색 탭은 검색 전에는 작품 목록을 표시하지 않습니다. 검색을 시작하면 `LibraryServicing`이 반환한 모든 섹션의 작품을 안정적인 작품 ID로 중복 제거한 뒤 제목과 작가에서 찾아 하나의 결과 목록으로 표시합니다. 특정 섹션 이름이나 Kavita의 `all-v2` 응답을 직접 찾아 사용하지 않습니다. 다른 공급자를 추가할 때도 검색 대상 전체가 섹션에 들어오도록 서비스 어댑터가 목록을 제공해야 합니다.
   **읽는 중** 카테고리에 있는 작품의 썸네일에는 홈, 이어서 읽기, 더 보기 화면 모두 상단에 붙은 각진 책갈피를 표시합니다. 표시 여부는 저장된 서재 목록에서 계산하며 별도 요청을 보내지 않습니다.
   전체 페이지를 읽었거나 **읽음으로 표시**한 작품은 각 목록의 표지 오른쪽 상단에 초록 체크를 표시합니다. 같은 작품에는 읽는 중 책갈피를 함께 표시하지 않습니다. 두 표시 모두 Kavita 목록의 `pagesRead`와 `pages`로 계산해 서재 목록 저장본에 보관합니다.
4. 작품 상세를 열면 저장된 챕터 목록을 먼저 복원하고, 저장본이 없을 때 Kavita에서 조회합니다. `GET /api/series/series-detail`의 `volumes`, `chapters`, `storylineChapters`, `specials`를 챕터 ID로 중복 제거한 뒤 일반 챕터와 Specials로 나눕니다. 일반 챕터를 먼저 표시하고 두 종류가 모두 있을 때만 구분선을 넣습니다. 챕터와 Specials 표지는 각각의 `chapterId`로 `GET /api/image/chapter-cover`에서 가져오며, 저장된 목록에서도 URL을 다시 만듭니다. 이전 형식의 챕터 캐시는 Specials가 빠져 있으므로 무시하고 다시 조회합니다. 상세 화면을 당겨 새로고침하면 서버 목록을 다시 가져옵니다. 리더는 `chapterId`와 페이지 번호를 사용해 Kavita 이미지 API에서 페이지를 가져옵니다. 뷰어의 1페이지는 표지를 포함한 원본 첫 이미지이며, 이미지 요청에서만 1부터 시작하는 뷰어 번호를 0부터 시작하는 Kavita 인덱스(`page = 뷰어 페이지 - 1`)로 변환합니다. 전체 페이지 수는 원본 그대로 사용하고, 진행률 저장·조회에는 기존 페이지 번호를 유지합니다. 이 변환은 첫 이미지 사전 로딩과 페이지 미리보기에도 공통으로 적용합니다. 상세 화면에서 연 리더는 조회한 목록을 전달받고, 홈의 계속 읽기에서 연 리더는 저장된 챕터 목록을 먼저 사용합니다. 페이지 경계에서 인접한 권이 있을 때만 이동 확인창을 표시합니다.
5. 읽기 진행률은 Kavita에 저장·조회하며, 일부 실패 경로에서는 앱 내부 저장값을 사용합니다.

## 읽기 버튼과 진행률

- 리더 이미지 사전 로딩은 현재 표시 범위의 이전 2페이지와 다음 2페이지를 포함합니다. 한 페이지 보기와 세로 스크롤은 최대 5페이지, 두 페이지 보기는 현재 2페이지를 포함해 최대 6페이지를 유지합니다. 첫 페이지 단독 표시에서는 실제 표시되는 1페이지를 기준으로 계산하며 권의 시작·끝에서는 존재하는 페이지까지만 로딩합니다. 표시 방식·읽기 방향·첫 페이지 단독 표시 설정을 바꾸면 사전 로딩 범위도 바로 갱신합니다.

- 리더의 페이지 선택기는 실제 이미지의 가로·세로 비율을 유지한 미리보기 카드 5장을 겹치지 않고 표시하며, 바깥 양옆 카드는 너비의 약 35%가 보이며 가장자리로 갈수록 흐려집니다. 카드 줄은 펼친 페이지 버튼의 바깥 너비보다 4pt 짧게 맞추고, 카드 내부 여백 없이 전체 이미지를 표시합니다. 카드에는 화면 배율에 따라 `1 / displayScale`pt인 1픽셀 검은 테두리와 3pt 모서리를 적용하고, 이미지·배경·테두리는 하나의 연속 곡률 도형으로 함께 잘라 모서리를 맞추고, 선택 페이지는 번호 배지 색으로 구분합니다. 이미지와 배경·테두리를 같은 합성 그룹으로 묶고 카드 줄 전체에도 합성 그룹을 적용해 펼침·접힘 시 함께 이동하며, 미리보기 이미지 자체에는 별도 등장 전환을 적용하지 않습니다. 검은 테두리는 펼침 애니메이션의 완료 콜백에서 표시하며, 접을 때는 먼저 60ms 동안 테두리를 숨긴 뒤 카드 이동을 시작합니다. 빠른 연속 조작과 화면 이탈에서는 이전 완료 콜백을 무효화합니다. 선택 페이지는 권의 시작·끝에서도 가운데를 유지하며, 존재하지 않는 이전·다음 페이지 자리는 비워 둡니다. 오른쪽에서 왼쪽으로 읽을 때는 배치를 반전합니다. 번호는 먼저 표시하고 미리보기를 받으면 이미지를 채웁니다. 선택 위치가 150ms 동안 유지된 뒤 선택 페이지부터 온전히 보이는 5장과 그 범위 바깥 양쪽 3장씩, 즉 선택 페이지 앞뒤 5장씩 최대 11장을 가까운 순서대로 한 번에 최대 2장씩 준비하며, 빠른 스크롤·막대 조작·목록 닫기 시 해당 미리보기 작업을 취소합니다. `ReaderViewModel`의 진행 중인 페이지 프리로드와 받은 원본 이미지를 먼저 재사용합니다. 부족한 이미지만 기존 페이지 API에서 받아 ImageIO로 최대 360px 썸네일을 만들며, 미리보기 조회는 독서 진행률을 변경하지 않습니다. 화면 밖 미리보기의 비율은 표시 카드 줄의 높이에 영향을 주지 않습니다. `PagePreviewCache`는 메모리에 최대 12MiB를 목표로 보관하고, JPEG를 `Caches/KavaReader/PagePreviews`에 최대 100MiB까지 저장합니다. 한도를 넘으면 최근 사용 시각이 오래된 파일부터 제거합니다. 캐시 파일명은 인증값을 포함한 페이지 URL의 해시로 계정·서버·권·페이지를 구분하며, 실제 URL이나 인증값을 기록하지 않습니다. 캐시가 없는 페이지의 최초 다운로드 용량은 줄지 않습니다.

- 작품 상세의 읽기 버튼은 서버·계정·작품 ID별로 `UserDefaults`에 저장된 읽기 상태를 즉시 표시합니다. 저장 키에는 서버와 계정 식별값의 해시만 사용합니다. 아직 확인된 상태가 없으면 **읽기**로 표시하며, 화면에 들어올 때마다 이어 읽기 API를 요청하거나 버튼을 로딩 상태로 바꾸지 않습니다. 읽기 상태는 목록 캐시와 별도로 보관합니다.
- 버튼을 누르면 대기 중인 진행률 저장이 끝난 후 `/api/reader/continue-point`에서 서버 위치를 확인합니다. 이어 읽기 응답과 이 기기의 마지막 위치가 다르면 `/api/reader/get-progress`로 마지막 챕터의 페이지도 확인합니다. 서버 진행률이 그 위치와 일치하면 마지막 챕터를 열고, 일치하지 않으면 두 위치 중 하나를 선택하게 합니다. 저장된 위치가 있으면 해당 페이지 이미지를 서버 확인과 동시에 미리 요청하고, 위치가 같을 때 재사용합니다. 확인된 위치와 이미지를 리더에 전달하므로 리더가 같은 챕터의 진행률을 다시 요청하거나 첫 페이지를 잠깐 표시하지 않습니다. 이미지 준비에 실패하면 리더에서 기존 방식으로 다시 요청합니다. 서버가 응답하지 않으면 저장된 위치로 열지 선택할 수 있습니다.
- 챕터를 열거나 페이지를 바꾸면 마지막 위치를 기기에 즉시 기록하고, 서버 저장 요청은 작품별로 순서대로 보냅니다. 오래된 저장 응답이 새 위치를 덮지 않도록 기록별 식별값을 확인합니다. 서버 저장에는 작품의 실제 라이브러리 ID를 사용하며, 이전 챕터 목록 캐시에 ID가 없으면 서버에서 조회합니다. 저장된 위치로 연 세션이나 챕터 진행률을 서버에서 확인하지 못한 세션은 진행률을 로컬에만 저장하고 서버에 자동 전송하지 않습니다.
- 작품 상세의 읽기 버튼 오른쪽 `…` 메뉴에서 **읽음으로 표시** 또는 **안 읽음으로 표시**를 선택할 수 있습니다. 후자는 모든 챕터의 진행률이 초기화되므로 확인창을 거칩니다. 두 동작은 각각 Kavita의 `POST /api/reader/mark-read`, `POST /api/reader/mark-unread`를 호출하며 `seriesId`와 `generateReadingSession: false`를 보냅니다. 서버가 성공을 반환한 뒤 기기에 남은 읽기 위치를 지우고, 서재 화면과 저장본의 체크·읽는 중 표시를 즉시 바꾼 다음 챕터 목록과 서버 서재 목록을 다시 가져옵니다.

## Favourite와 Want to Read

- **Favourite**는 앱에 별도 저장하는 좋아요가 아니라 Kavita 계정의 Want to Read 목록을 보여주는 카테고리입니다. 라이브러리 갱신 시 `POST /api/want-to-read/v2`의 모든 페이지를 읽고 기존 서재 목록 저장본에도 포함합니다. 이전 저장 형식에는 이 카테고리가 없으므로 복원 후 서버 목록을 갱신합니다.
- 작품 상세의 읽기 버튼 왼쪽 하트는 `GET /api/want-to-read?seriesId=`로 서버 상태를 확인합니다. 저장된 서재 목록에 상태가 있으면 먼저 표시하고, 서버 응답이 오면 이를 따릅니다. 하트를 누르면 `POST /api/want-to-read/add-series` 또는 `POST /api/want-to-read/remove-series`에 `seriesIds`를 보냅니다. 성공한 경우에만 하트와 라이브러리의 **Favourite** 목록 및 저장본을 갱신합니다. 실패하면 이전 상태를 유지합니다.
- Want to Read는 Kavita 자체 규칙을 따르므로, Kavita가 완독 작품을 목록에서 정리하면 다음 새로고침 때 **Favourite**에서도 사라집니다.

## 목록 캐시와 새로고침

- 서재와 챕터 목록 캐시는 항상 사용합니다. 라이브러리는 앱 시작과 서버 설정 변경 시 `Application Support/KavaReader/LibraryCatalog`의 저장본을 읽고, 작품 상세와 이어 읽기는 `Application Support/KavaReader/ChapterCatalog`의 작품별 저장본을 먼저 사용합니다. 저장본을 읽을 때는 Kavita에 목록 요청을 보내지 않습니다. 이전 버전에서 목록 캐시를 꺼둔 경우에도 저장본을 사용하고 새 목록을 기록합니다. **캐시 설정** 페이지에서는 커버 이미지 캐시만 관리합니다.
- **설정 → 서버 설정**의 서재 업데이트 버튼은 최근 추가·전체 작품 목록의 모든 페이지와 이어서 읽기 항목을 다시 가져오고, 전체 작품 응답에서 **읽는 중** 목록을 다시 계산합니다. 같은 화면에 마지막 목록 업데이트 시간을 표시합니다. 검색·라이브러리·설정 화면은 하나의 서재 상태를 공유하므로 설정에서 갱신한 결과가 두 탐색 화면에도 반영됩니다. 이전 형식의 서재 저장본을 읽은 경우에는 화면에 먼저 표시한 뒤 새 카테고리를 채우기 위해 서버 목록을 갱신합니다. 예전 이름으로 저장된 **읽는 중** 카테고리는 복원할 때 새 이름으로 표시합니다. 리더를 닫을 때는 진행률 저장이 끝난 뒤 서재 목록을 다시 가져와 **읽는 중** 카테고리를 갱신합니다. 작품 상세의 새로고침 버튼이나 당기기 동작은 챕터 목록을 다시 가져옵니다. 실패하면 이전 화면의 목록을 유지합니다. 수동 서재 새로고침이 성공하면 이전 커버 이미지 캐시도 비워 새 표지를 표시합니다.
- 홈은 각 섹션의 앞 8개만 보여주고, 더 보기 화면은 저장된 전체 섹션을 사용합니다. 두 저장 파일에는 목록 메타데이터만 기록하고 API Key가 담긴 커버 URL은 표시할 때 다시 만듭니다. 챕터 요청이 실패하면 저장본을 덮어쓰지 않고, 정상적으로 받은 빈 목록은 빈 목록 그대로 저장합니다. Kavita 만화 페이지 자체는 별도로 저장하지 않으므로 서버 작품의 오프라인 읽기는 지원하지 않습니다. 직접 가져온 파일 작품은 앱 내부의 압축 원본을 통해 오프라인으로 읽습니다.

## 라이브러리+ 실험 탭

- 조회 상태·검색 개수·실패·제한 정보는 일반 화면에 노출하지 않습니다. `DEBUG` 빌드에서만 우측 상단 개발 정보 버튼을 표시하고, 눌렀을 때 버튼에 붙은 작은 팝오버 패널에 진단 정보를 표시합니다. 진단 모델은 추천 모델과 관찰을 분리하므로 개별 조회 결과·진행률 변경이 추천 화면의 재계산을 유발하지 않습니다. 인덱싱 전체 작업이 완료되는 시점에 홈 구성을 한 번 갱신합니다.
- 라이브러리+는 기기의 로컬 날짜별로 구성한 서재 입력과 Kavita/AniList 메타데이터를 `LibraryPlus/*-daily.json`에 저장합니다. 탭 재진입·앱 재실행 시 당일 저장본을 복원하고 추천을 다시 선정하지 않습니다. 새로 실행된 앱에서는 미조회 정보를 수집하고, Kavita 조회와 AniList 보완 인덱싱이 모두 끝나면 최신 정보로 배너·추천 행·장르 목록을 다시 구성해 표시하고 당일 저장본에 저장합니다. 배너 후보와 추천 행은 최초 선정한 작품 ID·행 제목·순서를 당일 저장본에 함께 기록합니다. 화면은 미리 만든 표시 배열만 읽으며 탭 전환·배너 넘김·화면 재평가에서 추천 계산이나 전체 서재 변환을 수행하지 않습니다. 기존 입력만 저장된 파일은 같은 입력으로 한 번 계산한 뒤 선정 결과를 추가 저장합니다. 이어서 읽기는 공유 서재의 현재 목록을 사용하며, 당일 저장본이나 추천 준비 여부와 무관하게 1개부터 표시합니다. Kavita의 `latestReadDate`와 파일 작품의 `lastReadAt`을 UTC 시각으로 비교해 합친 목록 전체를 최근 읽은 순으로 정렬합니다. 시간대가 없는 Kavita 시각은 UTC로 해석하고, 읽은 시각이 없거나 유효하지 않은 항목은 뒤에 배치합니다. 같은 시각은 출처와 작품 ID로 정한 고정 순서를 사용합니다. 배너의 자동 슬라이드 전환은 유지합니다.
- 최초 준비 작업은 앱 루트가 소유한 모델에서 실행하므로 탭을 떠나도 취소·재시작하지 않습니다. 네트워크 요청 전에 이미 저장된 메타데이터로 전체 구성을 한 번만 표시·저장합니다. 이후 수집 결과는 메타데이터 캐시에만 기록하고 당일 저장본에는 적용하지 않습니다. 날짜가 바뀌면 새 구성을 준비하며 이전 구성이 있으면 준비가 끝날 때까지 유지합니다. 백그라운드에서 날짜가 바뀐 경우 앱 복귀 시에도 확인합니다.
- 이어서 읽기는 `ContinueReadingCollection`에서 출처별 캐시를 병합합니다. 서버 출처는 종류와 연결·계정 식별 문자열의 해시로 구분하고, 카드 ID는 출처와 서버 내 작품 ID(문자열 지원)로 구성합니다. 파일 출처는 현재 기기의 로컬 기록만 사용합니다. 실제 연결 설정과 어댑터는 아직 Kavita 한 개이며, Komga나 복수 서버 연결 UI는 구현하지 않았습니다. 추후 어댑터는 각 출처의 성공 응답만 교체하고 실패한 출처의 캐시는 유지하는 병합 경로를 사용할 수 있습니다.
- 이미지 뷰어에서 현재 페이지가 실제 표시되거나 EPUB 본문 복원이 완료된 뒤 읽기 활동을 반영해 해당 작품을 즉시 최근 순서로 올립니다. 이미지 다운로드·미리 읽기만으로는 활동을 만들지 않고, 콘텐츠 표시 전 로딩 실패 시 새 진행률을 저장하지 않습니다. 서버 작품의 임시 목록도 계정별 `<계정 해시>.continue.json` 캐시에 저장해 오프라인 재실행 시 복원합니다. 읽기 활동과 이어서 읽기 전용 갱신은 작은 목록 파일만 저장하고, 전체 서재 배열을 재구성하거나 전체 카탈로그 파일을 페이지마다 다시 쓰지 않습니다. 전체 서재를 저장할 때는 이 목록 파일도 같은 결과로 갱신합니다. 진행률 저장은 기존 서버별 저장 큐를 사용합니다. 성공한 서버 응답은 서버 기록을 기준으로 갱신하되, 요청 시작 뒤 발생한 읽기 활동은 늦게 도착한 응답으로 덮어쓰지 않습니다.
- 앱 실행 시 저장본을 먼저 표시하고 이어서 읽기 목록을 서버에서 갱신합니다. 저장본이 없거나 이전 형식이면 전체 서재를 조회합니다. 백그라운드에서 활성 상태로 복귀하면 대기 중인 서버 진행률 저장을 기다린 뒤 이어서 읽기 목록만 조회해 다른 기기의 기록을 반영합니다. 리더 종료 때는 저장 완료 후 기존 전체 서재 조회를 유지해 읽는 중·완독·총 진행률도 함께 갱신합니다. 이어서 읽기 전용 조회는 일일 추천 갱신 번호를 바꾸거나 표지 캐시를 비우지 않습니다. 요청 실패는 빈 목록과 구분하며 기존 목록을 유지합니다.

- **설정 → 서버 설정 → 라이브러리 업데이트**의 목록 조회가 성공했을 때만 계정별 영속 갱신 번호를 바꿉니다. 일반 독서 진행·찜 변경에 따른 목록 갱신은 이 번호를 바꾸지 않습니다. 독서 진행 갱신은 이어서 읽기에 즉시 반영되지만 추천 행을 다시 선정하지 않습니다. 서버나 API Key 변경 시에는 이전 계정의 메모리 구성을 즉시 비우고 해당 계정의 저장본을 사용합니다. 날짜·갱신 번호가 같은 중복 준비 요청은 서재 저장본을 새로 만드는 작업 전에 무시합니다. 최초 선정에서도 작품별 날짜 해시와 정규화된 장르·태그, 미시작 목록을 한 번 만들어 재사용합니다.
- 일일 저장본에는 기존 안전한 카탈로그 모델을 사용해 API Key와 커버 URL을 기록하지 않습니다. 이어 읽기 행은 공유 서재의 최신 챕터와 진행률을 표시하고 해당 챕터로 연결합니다. 추천의 중복 제한 계산에는 당일 입력을 유지해 이어 읽기 변경이 추천 행의 재선정을 유발하지 않도록 합니다. 페이지 진행률은 리더에서 확인합니다.
- 기존 라이브러리 옆에 별도 **라이브러리+** 탭이 있습니다. 먼저 Kavita의 작품별 `GET /api/Series/metadata?seriesId=` 응답에서 줄거리·장르·태그를 읽습니다. 카비타의 원본 파일과 메타데이터는 수정하지 않습니다.
- 상단 **오늘의 발견**에는 전체 서재에서 미완독 작품을 우선해 최대 5개를 고릅니다. 날짜와 작품 ID의 해시로 순서를 정해 하루 동안 일정하게 유지하고, 자동으로 6초마다 다음 작품을 보여줍니다. 스와이프로 직접 넘길 수 있으며 동작 줄이기 또는 VoiceOver 사용 중에는 자동 넘김을 멈춥니다. 이 선택은 AI 추천 점수가 아닙니다.
- 오늘의 발견 표지 뒤에는 해당 작품 첫 일반 챕터의 실제 페이지 최대 2장(가능하면 2~3페이지)을 회전 없이 가로로 겹쳐 표시합니다. 각 장의 수평 간격을 넓혀 기존 3장 배치의 전체 노출 너비(좁은 화면 30pt, 넓은 화면 42pt)를 유지합니다. 각 페이지의 위·아래 경계를 동일하게 맞추고, 로딩 전이나 조회 실패 시에는 해당 자리에 흰 페이지를 표시합니다. 이미지를 받는 순서대로 각 자리를 교체합니다. 활성 슬라이드에서만 로딩을 시작하고 슬라이드 전환·탭 이탈 시 진행 중 작업을 취소합니다. 기존 챕터 저장본을 우선 읽으며 없으면 작품 상세를 조회합니다. 페이지 이미지는 리더와 같은 이미지 API로 가져와 최대 600px JPEG로 축소합니다. 두 페이지와 챕터·페이지 번호는 별도 `Caches/KavaReader/FeaturedPreviews/day-*` 폴더에 기기 현지 날짜가 같은 동안 저장하며, 앱 재실행이나 탭 전환에서도 먼저 복원합니다. 파일명은 서버·API Key·작품 ID의 해시이며 URL과 인증값은 파일 내용에 저장하지 않습니다. 한 장씩 저장하여 중간 취소 후에는 부족한 페이지만 다시 요청합니다. 날짜 변경, 다음 실행, 캐시 조회·저장 때 전날 폴더를 삭제하며 자정을 넘겨 완료된 이전 날짜 요청은 다시 저장하지 않습니다. 앱이 종료된 동안의 만료 파일은 다음 실행 때 삭제합니다. 계정·작품·날짜가 바뀌면 화면의 미리보기도 비웁니다. 미리보기 조회는 독서 진행률과 기존 커버 캐시를 변경하지 않습니다.
- 배너 아래에는 **이어서 읽기 → 개인화 행 최대 2개 → 테마 행 최대 5개**를 표시합니다. 이어서 읽기는 `POST /api/Series/on-deck`의 작품 목록(`id`, `name`)을 읽고, 각 작품의 `/api/reader/continue-point`와 챕터 목록을 조회해 정확한 챕터·권·페이지 위치를 구성합니다. 서버 순서대로 최대 10개를 구성하며, 특정 작품의 위치 조회가 실패해도 다른 작품은 유지합니다. 1개부터 표시하며, 라이브러리와 라이브러리+ 모두 카드를 누르면 해당 작품의 상세 화면으로 이동합니다. 실제 이어 읽기는 상세 화면의 읽기 버튼에서 시작합니다. 과거 응답 형식 오류로 비어 있는 이어 읽기 목록이 저장된 기기도 복구하도록 서재 저장 형식을 5로 올려 이전 저장본을 표시한 뒤 자동으로 갱신합니다. 개인화·테마 행은 후보가 최소 4개 있어야 하며 행당 최대 12개를 표시합니다. **찜한 작품**은 1개부터 표시하고 개인화 2자리 중 우선 배치합니다. 조건을 만족하는 행이 부족하면 적게 표시합니다.
- 개인화 후보는 **취향에 맞는 작품 / 찜한 작품 / 새로 추가된 작품 / 오늘 시작해 볼 작품 / 새로운 장르 탐색 / 이 작품이 마음에 들었다면**의 6개입니다. 새로운 장르 탐색은 선호 장르와 새로운 장르를 함께 가진 작품을 고릅니다. 유사 작품 행은 관련 미시작 후보가 4개 이상인 기준 작품을 골라 영어로 `Because you read 작품명`, 한국어로 `읽으신 작품명 기반 추천`을 표시합니다. 기준은 현재 서버에 있는 작품 전체 페이지의 50% 이상을 읽었거나 완독한 작품이며, 진행률이 없거나 찜만 한 작품은 제외합니다. 완독 후보를 먼저 확인하고, 같은 완독 여부 안에서는 읽은 비율(0~100점)에서 최근 선정 감점을 뺀 순서로 확인합니다. 어제 선정된 작품은 무조건 제외하며, 2일 전 선정은 30점 감점하고 하루 오래될 때마다 감점을 0.85배로 줄입니다. 최근 30일의 반복 선정 감점은 누적하며 그보다 오래된 이력은 점수에 반영하지 않습니다. 동점은 날짜·작품 ID 해시로 정합니다. 조건을 충족하는 기준이 없으면 이 행을 표시하지 않습니다. 이 행은 찜한 작품 다음 개인화 슬롯을 우선 사용합니다. 찜한 작품 외의 개인화 행과 테마 행 순서는 날짜별 해시로 정합니다.
- 테마는 **다른 세계로 떠나는 모험 / 먼치킨 / 한 수 앞을 읽는 두뇌전 / 단서를 따라가는 미스터리 / 긴장감 넘치는 생존 이야기 / 설레는 로맨스 / 웃음과 설렘 사이 / 학교 이야기 / 편안한 일상물 / 한바탕 웃고 싶을 때 / 승부에 빠져드는 순간 / 미래와 기술을 상상하다 / 서늘한 이야기 / 맛있는 만화 / 회귀와 두 번째 기회 / 새로운 삶, 환생 / 복수의 시작 / 던전과 공략 / 게임 속 세계 / 마법과 마술 / 무림과 무협 / 검과 검술 / 역사 속 이야기 / 직장 이야기 / 음악과 무대 / 예술과 창작 / 가족 이야기 / 동물과 함께 / 여행과 방랑 / 라이벌과 경쟁 / 팀으로 성장하는 이야기 / 악역의 시선 / 정치와 권력 / 인간과 다른 존재들**의 34개입니다. 개인화 후보 6개와 합쳐 추천 행은 총 40종입니다. 먼치킨은 압도적으로 강한 주인공 태그로 분류하며 단순 성장·수련 태그로 선정하지 않습니다. 장르·태그의 한글·영문 동의어를 정규화하고 제목이나 줄거리로 추정하지 않습니다. 팀으로 성장하는 이야기는 팀·동료 중심 태그와 성장 태그 또는 스포츠·모험 장르를 함께 요구합니다. 가족 이야기는 가족생활·부모와 자녀·육아 태그로 고르고, 인간과 다른 존재들은 인외·안드로이드·흡혈귀 주인공 태그로 고릅니다. 일반 가족·흡혈귀 등장만으로 선정하지 않습니다. 새 행도 당일 저장된 선정 결과에는 끼워 넣지 않으며 다음 날 또는 설정의 라이브러리 업데이트 시 후보로 사용합니다.
- 전체 페이지 수와 읽은 페이지 수는 Kavita 작품 목록 응답에서 가져와 서재 형식 6에 함께 저장합니다. 이전 서재 저장본은 자동 갱신하며 갱신 전에는 새 추천을 확정하지 않습니다. 유사 작품의 실제 노출 기준 ID·날짜는 계정별 `LibraryPlus/*-anchors.json`에 30일 이력으로 저장합니다. 앱 재실행·서버 전환·같은 날 수동 업데이트에도 전날 사용 이력이 유지됩니다. 예전 당일 파일의 기준 작품명도 유일한 작품 ID로 확인할 수 있으면 이력에 복원합니다. 추천 알고리즘 버전이 없는 이전 당일 저장본은 새 정책으로 한 번 다시 선정합니다.
- 새 추천은 미시작 작품만 대상으로 하며 읽는 중·이어 읽기·완독 작품은 제외합니다. 새로 추가된 작품은 서버의 최근 추가 순서를 유지하고 나머지 무점수 후보와 동점 후보는 하루 동안 순서를 유지합니다. 독서 상태·즐겨찾기가 바뀌어도 당일 행 구성은 유지하며, 다음 날 또는 설정의 라이브러리 업데이트 후에 반영합니다.
- 화면 전체에서 한 작품은 배너와 이어 읽기를 포함해 최대 2회까지 노출합니다. 반복 제한 적용 후에도 각 행의 최소 작품 수를 충족해야 합니다. 표시할 작품 집합이 기존 추천 행과 작은 행 기준 70% 이상 겹치면 그 행을 건너뛰고 다음 후보를 검토합니다. 정보가 부족한 테마를 임의의 작품으로 채우지 않습니다.
- 당일 화면 구성과 별개로 작품별 정보를 최대 4개씩 병렬로 조회합니다. 성공한 응답은 `Application Support/KavaReader/LibraryPlus`에 서버·API Key 조합의 해시 파일명으로 저장합니다. 파일에는 API Key나 커버 URL을 저장하지 않습니다. 일반 수집에서는 새 작품 또는 실패한 작품만 다시 조회하며, 설정의 라이브러리 업데이트 후에는 전체 정보를 다시 확인합니다. 업데이트 시에도 이미 저장된 정보로 먼저 당일 구성을 확정하고, 이후 새로 조회한 정보는 다음 날짜 또는 다음 명시적 업데이트에서 사용합니다. 라이브러리+에는 별도 새로고침 버튼을 두지 않습니다.
- 카비타 장르·태그가 모두 비어 있는 작품은 제목을 AniList의 공개 만화 API에서 검색합니다. 제목 또는 별칭을 정규화해 정확히 일치하는 후보가 하나일 때만 장르와 스포일러가 아닌 높은 관련도의 태그를 사용합니다. 일치하지 않거나 후보가 여러 개면 분류하지 않습니다. 카비타 장르·태그가 하나라도 있으면 외부 분류보다 우선합니다. 이 과정은 AI 추론이 아닙니다.
- AniList 검색은 읽는 중·즐겨찾기 작품과 최근 ID를 우선해 순차적으로 수행하고 요청 시작 시점을 최소 2.5초 간격으로 유지합니다. 앱의 하루 검색 개수 제한은 없습니다. 유효한 저장 결과가 없는 모든 대상 작품을 순차 검색합니다. 429 응답을 받으면 `Retry-After` 동안 중단합니다. 최소한의 일치 결과를 별도 파일에 저장하고 일치 결과는 1년(365일), 일치 없음은 30일 후 다시 확인합니다. 기존 저장 결과에도 같은 유효기간을 적용하며, 작품 제목이 바뀌면 유효기간과 관계없이 다시 확인합니다. 카비타 메타데이터와 마찬가지로 외부 응답도 원본 파일에 쓰지 않습니다.
- 작품 상세 화면의 정보 버튼은 해당 작품의 카비타 메타데이터를 직접 확인하고, 라이브러리+에 저장된 AniList 일치 정보가 있으면 함께 보여 줍니다. 제목·서재·요약·장르·태그에 출처를 표시하며, 추천 분류에서는 직접 연결한 AniList 장르·태그를 최우선으로 사용하며, 자동 연결인 경우 카비타 장르·태그를 우선합니다. 정보 패널을 열 때 외부 API를 새로 검색하지 않습니다.
- 작품 상세의 정보 패널에서 **작품 연결 / 연결 변경**을 누르면 AniList를 직접 검색하고 후보를 선택할 수 있습니다. 검색 버튼이나 키보드 검색을 실행할 때만 요청하며 한 글자 검색도 허용합니다. 결과는 20개씩 추가 조회하며 표지·원제·작가·연도·만화/단편 형식을 표시하고 소설은 제외합니다. 선택한 후보의 장르와 스포일러가 아닌 높은 관련도의 태그를 확인한 뒤 연결합니다. 자동 제목 매칭 규칙은 그대로 유지하며, 분류가 없는 후보도 사용자 연결은 저장합니다. 검색 표지는 AniList 공개 URL을 `AsyncImage`로 표시하며 Kavita 커버 캐시에는 저장하지 않습니다.
- 사용자 연결은 서버·API Key 조합의 해시와 Kavita 작품 ID로 구분한 `LibraryPlus/*-manual-anilist.json`에 별도로 저장합니다. 제목 변경·자동 검색 캐시 만료·재인덱싱에도 연결을 유지하며 기기 간 동기화나 서버·원본 파일 수정은 하지 않습니다. 사용자가 직접 연결한 AniList 분류는 자동 검색과 Kavita 분류보다 우선합니다. 변경 알림을 받으면 저장된 정보만으로 당일 장르 탐색과 추천을 갱신하며 전체 인덱싱을 다시 시작하지 않습니다. 인덱싱 중 변경도 최종 저장 직전에 사용자 선택을 다시 반영합니다.
- **연결 해제**는 해당 작품의 자동 연결도 중지하는 기록을 남겨 다음 인덱싱에서 같은 후보에 다시 연결되는 것을 막습니다. **자동 연결 사용**으로 중지를 해제할 수 있습니다. 수동 연결의 **연결 정보 새로고침**은 저장한 AniList ID를 직접 조회하고, 실패하면 기존 연결을 유지합니다. 사용자 검색은 429 응답의 `Retry-After` 동안 재요청을 중지하고 오류를 표시합니다.
- 읽는 중·즐겨찾기 작품의 장르와 태그를 기준으로 미시작 작품에 공통 항목 점수를 매깁니다. 점수가 있는 작품만 **취향에 맞는 작품** 행에 넣고 오늘의 발견 배너에서도 우선합니다. 점수는 장르 공유에 더 큰 가중치를 두며, 동점일 때는 날짜별로 정한 순서를 사용합니다. 분류가 없는 작품에는 점수를 만들지 않습니다.

## 인증 및 저장 위치

- 작품 정보 패널 하단의 커스텀 장르/태그 추가 버튼은 입력 필드가 있는 알림창을 열며 저장 즉시 분류에 반영합니다. 빈 값과 같은 분류의 대소문자 중복은 추가할 수 없습니다. 커스텀 항목은 강조 색상으로 구분하고 출처에 커스텀을 함께 표시합니다. 커스텀 항목이 하나라도 있으면 전체 삭제 버튼을 표시합니다. `CustomSeriesCategoryStore`는 서버·계정 해시와 작품 ID(로컬 파일은 서버와 무관한 UUID)로 구분해 기기의 UserDefaults에 별도 저장하며 기존 개발용 저장 키를 유지합니다. Debug와 Release 모두 정보 화면, 장르 탐색과 추천에 적용하며 원본 파일·Kavita·AniList 데이터는 수정하지 않습니다. 당일 추천과 선택 이력의 Debug/Release 캐시 분리는 유지합니다.
- `MetadataCategoryRegistry`는 번역표와 명시적 동의어를 안정적인 장르/태그 ID로 연결합니다. 새 커스텀 항목은 알려진 ID로 저장하며 기존 한국어/영어 문자열도 읽을 때 같은 ID로 비교합니다. 정보 표시, 병합과 중복 검사, 장르 탐색과 추천이 같은 기준을 사용하고 원본 문자열은 유지합니다. 미등록 자유 입력은 원문으로 보존하며 여러 분류가 같은 번역명에 대응하면 후보를 선택합니다. 분류 기준 변경에 맞춰 일일 추천 버전은 3으로 올려 기존 선정 결과를 재계산합니다. 언어 확장 규칙은 `docs/metadata-localization.md`에 설명합니다.

- 사용자명·비밀번호·API Key·로그인 토큰은 서버의 스킴·호스트·포트·하위 경로를 정규화한 식별자별로 Keychain에 저장합니다. 호스트 대소문자, 기본 포트, 끝 슬래시는 같은 서버로 취급하며 HTTP/HTTPS 및 서로 다른 하위 경로는 분리합니다. 평문 설정에는 서버 URL과 비밀정보를 담지 않는 변경 번호만 둡니다.
- 기존 공용 로그인 정보는 서버 소속을 보장할 수 없어 앱 시작 시 제거합니다. 업데이트 후 로그인 정보 재입력이 필요합니다. 서버 주소를 바꾸면 해당 서버의 로그인 정보만 표시하고 요청에 사용합니다. API Key는 보안 입력란으로 표시합니다.
- 인증·라이브러리 통신은 서버별 임시 URLSession과 쿠키 저장소를 사용합니다. 다른 서버·포트·하위 경로로 향하는 리다이렉트를 차단하고, 쿠키 로그인은 앱 종료 시 만료됩니다. 커버 요청은 현재 서버 범위 안에서만 인증 헤더를 붙입니다. 이미지 API Key 쿼리 전달은 기존 Kavita 호환 동작으로 유지합니다.

- 서버 설정의 서버 유형 목록에 **Kavita / Kavita OPDS**를 별도 항목으로 표시합니다. `KavitaConnectionType`에 따라 Kavita 화면은 서버·계정 입력과 연결 테스트·로그인 버튼을, Kavita OPDS 화면은 주소와 연결 버튼만 표시합니다. 화면 안의 입력 방식 선택기는 제거했습니다. 두 유형은 같은 활성 서버 URL과 Kavita API 서비스를 사용합니다. 로그인 정보는 서버별로 보관하지만 활성 서버는 하나이며, 서버 목록 UI나 OPDS 피드 공급자는 제공하지 않습니다.
- Kavita 3rd Party Clients의 API Key를 `POST /api/Plugin/authenticate`에 전달해 Bearer JWT를 발급받고, 목록 API에 Bearer 토큰을 전달합니다. 연결 테스트와 로그인 버튼은 같은 인증 흐름 뒤 `/api/Library/libraries`를 호출해 API 접근까지 확인합니다.
- 사용자명·비밀번호 로그인은 이전 호환 경로로 남아 있습니다. 일반적인 Kavita 연결에는 사용자 설정의 Auth Key를 사용합니다.
- 작품·권 커버 이미지는 유효한 이미지 응답만 앱의 `Caches/CoverImages`에 저장합니다. URL과 계정 인증값을 해시한 파일명으로 구분하며, 다시 표시할 때 디스크 캐시를 먼저 읽습니다. 설정에서 캐시를 끄면 저장본을 읽거나 새로 저장하지 않고 서버에서 다시 받습니다. 설정에는 현재 저장 용량과 캐시 삭제 기능이 있습니다. iOS가 `Caches` 폴더를 정리하면 이미지는 필요할 때 다시 내려받습니다.

### Reading pause and progress reset

The series detail options menu separates “Not reading anymore” from “Reset reading progress”.
Stopping waits for pending progress saves, then POSTs `/api/Series/remove-from-on-deck?seriesId=…`
without changing chapter progress. `ReadingPauseStore` persists account-scoped paused series IDs;
`LibraryViewModel` filters these from Reading and Continue Reading while retaining the unfiltered
catalog snapshot for subsequent mutations and disk saves. Opening the reader and recording progress
clears the pause. Resetting requires a confirmation and uses the existing Kavita mark-unread API,
then clears saved local reading positions and the pause state only after server success.

## 로컬 파일 라이브러리

- `LocalComicPicker`는 파일 앱의 기기/iCloud/File Provider에서 파일 여러 개 또는 폴더 하나를 선택합니다. 폴더 접근 범위는 가져오기 동안 유지하고, 디렉터리 탐색은 별도 작업에서 수행합니다. `LocalComicStore` actor가 NSFileCoordinator로 파일 읽기를 조정해 다운로드된 내용을 복사합니다.
- CBZ·ZIP의 저장/Deflate 압축에서 이미지 페이지를 읽습니다. `ComicArchive`는 중앙 디렉터리와 로컬 헤더 범위를 확인하고, 페이지별 크기 제한(100 MiB)·길이·CRC를 검사합니다. 암호화/ZIP64 및 다른 압축 형식은 오류로 표시합니다. 이미지 이름은 자연 정렬하고 macOS 리소스 파일은 제외합니다. 원본 항목의 경로로 파일을 풀어 쓰지 않습니다.
- `Application Support/KavaReader/LocalComics/catalog.json`에 작품 UUID, 권 UUID, 상대 보관 경로, 파일 SHA-256, 페이지 수, 용량, 즐겨찾기와 진행률을 저장합니다. 표지는 최대 1024픽셀 썸네일로 생성하고, 본문은 압축 원본에서 필요한 페이지를 읽습니다. 한 번에 한 권의 압축 인덱스를 보관합니다.
- 한 파일을 완료할 때마다 카탈로그를 원자적으로 저장합니다. 중복 파일은 건너뛰고, 실패한 파일이 있어도 다음 파일을 처리합니다. 중단 후 동일 파일/폴더를 다시 선택하면 완료한 파일은 건너뜁니다. 가져오기 작업 자체의 자동 재개는 하지 않습니다.
- 폴더의 상대 경로를 작품명으로 사용합니다. 개별 파일은 각각 작품으로 등록하며, 파일 관리에서 작품 이름 변경과 작품 합치기를 제공합니다. 기존 작품에는 `권 추가`로 파일을 가져올 수 있습니다. 합친 권의 보관 경로는 유지하고, 삭제할 때 다른 작품이 참조하는 폴더는 보존합니다. 가져온 원본 파일은 수정하거나 삭제하지 않습니다.
- `LibraryViewModel`은 서버 저장본을 적용한 뒤 로컬 작품을 표시 배열에 합칩니다. 서버 카탈로그 저장 시 로컬 ID는 포함하지 않으며, 서버 변경에도 파일 작품은 유지합니다. 라이브러리의 Favourite는 두 출처를 합치고, Kavita와 Files는 출처별 목록입니다. 이전 All Series 선택값은 Kavita로 전환합니다.
- 작품 상세와 ReaderView는 공유합니다. `isLocal` 표시가 있는 파일 작품은 로컬 상세/페이지/진행률 경로를 사용합니다. 진행률 저장은 읽기 저장 큐를 통해 순서를 유지하고, 로컬 변경 알림은 짧게 모아 서재를 갱신합니다.
- 파일 작품이 있을 때 홈의 배너, 추천 행, 장르 탐색, 이어 읽기는 두 출처를 함께 사용합니다. 전체 컬렉션 정렬은 카탈로그/날짜/메타데이터 입력이 바뀔 때 계산해 화면 배열에 보관합니다. 정보가 없는 파일에 임의의 장르를 부여하지 않습니다. 기기 간 동기화와 외부 폴더 자동 연결은 후속 작업입니다.

## 로컬 EPUB 리더 (기존 저장본 호환용)

- 새 파일 가져오기는 CBZ·ZIP만 허용합니다. 파일 선택과 폴더 탐색에서 `.epub`을 제외하고 저장소의 가져오기 진입점에서도 거절합니다. 아래 EPUB 처리 코드는 기존 저장본 호환을 위해 유지합니다. `ComicArchive(includeAllEntries: true)`로 EPUB의 문서·이미지·스타일·폰트를 읽습니다. 기존 이미지 압축 만화의 정렬/읽기 경로는 유지합니다. 빈 리소스 파일과 저장/Deflate 압축을 처리하고, 리소스마다 압축 전후 크기를 제한합니다.
- `EpubPublication`은 `mimetype`, `META-INF/container.xml`, OPF manifest/spine을 확인합니다. 제목·작가, EPUB 3 cover-image/EPUB 2 cover 메타데이터, EPUB 3 nav/EPUB 2 NCX의 본문 제목과 고정 배치 여부를 읽습니다. 본문 순서는 파일명 대신 spine을 따릅니다. XML 외부 엔티티와 DTD를 금지하고, 참조 경로는 아카이브 내부로 제한합니다. encryption.xml에 암호화 항목이 있으면 가져오기를 거절합니다.
- `LocalComicVolume.epub`와 `epubLocation`에 본문 구조 및 구간/스크롤 비율을 저장합니다. 새 필드는 선택적이므로 기존 CBZ·ZIP 저장본도 읽습니다. 기존 표지 없는 EPUB 저장본도 읽을 수 있으며, `LocalComic.author`와 `coverAvailable`로 작품 정보 및 표지 표시를 관리합니다.
- `SeriesChapter.isEpub`에 따라 `ReaderView`가 `EpubReaderView` 또는 기존 이미지 리더를 표시합니다. 텍스트 EPUB에 이미지 페이지 프리페치를 시도하지 않습니다. EPUB 상세에는 가상 페이지 수 대신 EPUB 형식을 표시합니다.
- `EpubReaderView`는 본문 목록, 이전/다음 구간, 글자 크기, 완독 표시를 제공합니다. `WKURLSchemeHandler`로 해당 권의 manifest에 있는 리소스만 제공하고 파일을 외부 경로에 풀지 않습니다. WKWebView 데이터 저장소는 임시 저장소를 쓰고, 콘텐츠 JavaScript와 원격 탐색/리소스 요청을 막습니다. 앱의 표시 스타일은 별도 WKContentWorld에서 적용합니다. 고정 배치 EPUB은 원본 스타일/viewport를 유지하며 글자 크기 조절을 제공하지 않습니다.
- 스크롤 변경은 잠시 모아 읽기 큐에 저장하고, 화면 종료 시 남은 위치를 저장합니다. 공통 진행률 필드에는 본문 하나당 1000단위로 환산해 완독/이어 읽기를 기존 홈과 공유합니다. 정확한 복원 정보는 본문 인덱스와 스크롤 비율이며, EPUB을 실제 1000페이지로 표시하지 않습니다. 초기화는 이 위치도 제거합니다.
- EPUB의 새 가져오기는 현재 지원하지 않습니다. 기존 저장본의 읽기 경로만 유지합니다. Kavita EPUB 연동, DRM/폰트 난독화 해제, 스크립트 기반 인터랙티브 콘텐츠, 원격 리소스는 구현하지 않습니다.
- 구조 참고: [W3C EPUB 3.3](https://www.w3.org/TR/epub-33/), [Apple WKURLSchemeHandler](https://developer.apple.com/documentation/webkit/wkurlschemehandler).

## 출처별 장르·태그 우선순위

- Kavita 작품: 수동 AniList 연결이 없으면 계정별 Kavita 메타데이터를 우선하고, 장르와 태그가 모두 없을 때 AniList를 사용합니다. 파일 작품은 Kavita 요청이나 서버의 정수 ID 캐시에 포함하지 않습니다.
- 직접 가져온 파일: EPUB OPF의 `dc:subject`를 분류로, `dc:description`을 줄거리로 읽습니다. 명시적인 genre/tags/keywords 및 calibre 태그 필드도 읽습니다. CBZ·ZIP은 루트 또는 유일한 하위 `ComicInfo.xml`의 `Genre`, `Tags`, `Summary`를 읽습니다. 표준 주제 문자열은 복합 이름을 유지하고, ComicInfo 및 사용자 정의 목록 필드는 쉼표/세미콜론/개행으로 나눕니다. HTML과 빈 값, 대소문자 중복은 정리합니다.
- 수동 AniList 연결이 없을 때 파일의 장르나 태그 중 하나라도 있으면 내장 분류 전체를 우선합니다. 둘 다 없을 때 외부 분류를 사용하며, 파일명이나 줄거리에서 장르를 추측하지 않습니다. 여러 권을 합친 작품은 내장 분류를 중복 없이 합칩니다.
- 권별 선택적 `embeddedMetadata`와 `metadataVersion`을 저장합니다. 기존 가져오기 카탈로그는 아카이브에서 메타데이터만 읽어 보완하며, 즐겨찾기·진행률·보관 경로는 유지합니다. 한 파일이 읽히지 않아도 다른 작품 처리를 계속합니다.
- `LocalSeriesMetadataStore`는 작품 UUID로 기기별 자동 검색 결과와 수동 연결을 `local-files-metadata.json`에 저장합니다. Kavita 계정 전환과 독립적입니다. 제목 변경은 자동 검색 결과를 무효화하고, 일치 결과는 365일, 검색 결과 없음은 30일 보관합니다. 요청을 2.5초 간격으로 보내고 429 제한을 저장하여 재실행 후에도 대기합니다. 통신 실패를 검색 결과 없음으로 저장하지 않습니다. 사용자가 직접 연결한 AniList 작품의 장르·태그는 Kavita 및 파일 내장 분류보다 우선합니다. 분류가 없는 AniList 작품을 직접 선택했으면 미분류로 표시합니다. 연결 해제는 자동 검색을 중지하고 Kavita/파일 내장 분류로 돌아갑니다. 줄거리는 원래 출처의 정보를 유지합니다. 일일 추천 저장본에는 수동 연결 여부를 보관하며 구버전 선정 결과는 갱신합니다.
- EPUB 파일의 외부 검색은 AniList의 NOVEL 후보도 허용합니다. 자동 연결은 제목/별칭이 정확히 일치하는 유일한 후보만 사용하고 스포일러 태그는 제외합니다. AniList에 없는 일반 도서는 미분류 상태로 유지하며, 수동 연결 검색에서도 확인한 작품을 선택할 수 있습니다.
- 홈 추천은 UUID로 출처 간 후보를 구분하며 파일 장르·태그도 취향 추천/테마 추천에 사용합니다. 장르 탐색과 작품 정보의 출처 표시도 같은 우선순위를 따릅니다. 로컬 메타데이터 작업은 읽기 진행률 알림마다 재시작하지 않고, 가져오기/작품 변경/수동 연결/앱 재진입 때 준비합니다.
- 구조 참고: [EPUB 3.3](https://www.w3.org/TR/epub-33/), [ComicInfo 필드](https://anansi-project.github.io/docs/comicinfo/documentation), [AniList Media](https://anilist.gitbook.io/anilist-apiv2-docs/docs/reference/object/media).

## 파일 추가 직후 인덱싱 현황

- 파일 가져오기 저장 알림을 받으면 `AppRootView`가 바로 로컬 메타데이터 작업을 시작합니다. 서재 표시 갱신만 250ms 모아서 처리하므로 홈 방문이나 가져오기 완료를 기다릴 필요가 없습니다. 기존의 동일 카탈로그 요청은 제목/권 목록/메타데이터 버전 키로 건너뛰며 읽기 진행률 알림마다 검색을 다시 시작하지 않습니다.
- `LibraryPlusViewModel.localDiagnostics`는 내장 정보 처리 수/전체 수와 필요한 외부 검색 처리 수/전체 수를 별도로 보관합니다. 수동 연결, 유효한 캐시 및 내장 분류가 있는 작품은 외부 검색 대기 수에 포함하지 않습니다. 완료/취소/실패 시 작업 상태를 종료하며 이전 작업 취소가 새 작업의 진행 표시를 지우지 않게 작업 ID를 검사합니다.
- `LibraryIndexingStatus`가 기존 홈의 인덱싱 표시를 공유합니다. 홈에서는 진행 중인 서버/파일 작업을 표시하고, 라이브러리의 파일 컬렉션에서는 작품 그리드 아래에 파일 작업 현황만 표시합니다. 로딩 아이콘, 문구, 진행바, 처리 수/전체 수와 안내문을 그대로 사용하며 작업 종료 후 숨깁니다. 필터로 작품이 보이지 않아도 진행 중인 파일 인덱싱 현황은 표시합니다.
- 작업은 뷰 모델이 소유하므로 탭 전환이나 가져오기 화면 종료로 취소하지 않습니다. 파일 추가/삭제/이름 변경 등 입력 변경 시 새 카탈로그 작업으로 교체하며 완료된 자동 검색 캐시는 재사용합니다.

## 다른 언어 제목으로 재검색

- 설정 → 고급 설정 → 인덱싱의 `다른 언어 제목으로 재검색`은 기본 OFF이며 `indexing_alternate_title_search`로 기기에 저장합니다. ON일 때만 한글 제목의 자동 AniList 검색 실패 후 한국어 위키백과 Action API를 호출합니다. 별도 검색 API 키나 개발자 서버는 사용하지 않습니다.
- `WikipediaTitleService`는 제목과 `(만화)`/`(소설)` 문서 및 리다이렉트의 영어 언어 링크를 확인합니다. 동음이의 문서는 제외하고 서로 다른 영어 제목이 여러 개면 자동 연결하지 않습니다. 영어 제목의 작품 종류 접미사만 제거하여 AniList에 재검색하며, 기존의 유일한 정확한 제목/별칭 일치 및 분류 존재 조건을 유지합니다. 위키백과에 문서/영어 링크가 없는 작품, 영제와 AniList 등록명이 다른 작품은 미분류로 남습니다. 범용 웹 검색이나 AI 번역은 구현하지 않습니다.
- Kavita/파일 내장 장르·태그 또는 수동 연결이 있으면 보조 검색을 하지 않습니다. 성공한 메타데이터는 기존 캐시에 보관하며 OFF로 바꿔도 유지합니다. 캐시에 선택적인 `alternateTitleSearchAttempted`를 기록하여 구버전 캐시를 읽을 수 있고, ON 전의 한글 제목 검색 실패는 즉시 재시도 대상으로 취급합니다. 보조 검색까지 실패한 결과는 기존 30일 실패 캐시를 따릅니다. 네트워크 실패·취소는 제목 없음으로 저장하지 않습니다.
- 설정 변경은 로컬 인덱싱을 다시 준비하고 홈의 서버 인덱싱 요청 키를 갱신합니다. AniList 재검색 전에는 2.5초 간격을 유지하고 429의 대기시간과 작업 취소를 처리합니다. 위키백과로 작품 제목이 전달되는 사실을 설정 설명과 개인정보 처리방침에 표시합니다.

- 동명 작품 자동 연결 방지: 한글 제목의 정확한 일치 후보가 둘 이상이면 영어 제목 보조 검색도 진행하지 않고 건너뜁니다. 영제 검색에서도 동명 후보가 둘 이상이면 미분류 상태로 유지합니다. 장르가 없는 후보나 소설판도 동명 판정에 포함합니다. 자동 검색은 최대 50개 후보를 조회하며 다음 페이지가 남으면 유일성을 확인할 수 없으므로 연결하지 않습니다. 위키백과에서도 실재 문서가 여럿이거나 동음이의 문서가 있으면 영제를 고르지 않습니다. 사용자는 작품 상세의 기존 수동 AniList 연결에서 직접 선택할 수 있습니다.

## Kavita 연결 방식별 설정

- 서버 설정의 Kavita 직접 연결과 Kavita OPDS는 별도 Keychain 프로필(`kavita.connection.profile.direct` / `.opds`)로 입력을 보관합니다. OPDS 주소의 키를 직접 연결 입력란에 복사하지 않습니다. 프로필과 OPDS 전체 주소는 UserDefaults에 저장하지 않습니다.
- 직접 연결은 서버 주소와 인증 방식 선택(API 키 / 계정 로그인)으로 구성하고 선택한 인증 입력만 표시합니다. 두 화면 모두 연결 버튼 하나로 인증과 라이브러리 접근을 확인합니다. 계정 로그인은 `/api/Account/login`의 토큰으로 `/api/Library/libraries`까지 확인합니다.
- 입력 중에는 활성 서버를 바꾸지 않습니다. 검증과 저장 성공 후에만 기존 런타임용 서버 주소와 인증 정보를 갱신하고 `kavita_active_connection_type`으로 현재 사용 중인 방식을 표시합니다. 저장 실패 시 이전 인증 정보를 복원합니다. 한 번에 활성 연결은 하나이며, 각 설정 화면의 저장값은 독립적으로 유지합니다.
- 기존 저장 정보는 연결 경로를 식별할 수 없으므로 활성 연결을 그대로 유지하되 어느 입력 화면에도 자동 복사하지 않습니다. 다음 연결 성공부터 방식별 프로필과 사용 중 표시를 보관합니다.
